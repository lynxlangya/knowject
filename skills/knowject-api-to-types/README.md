# knowject-api-to-types

## What It Does

`knowject-api-to-types` generates TypeScript response types from OpenAPI 3 and can wire those types into clients produced by `knowject-read-api`. It completes the typed-client flow by replacing `request<unknown>(...)` response generics when the generated client has the expected header marker.

Day-1 scope is response typing only. Request bodies, query params, path params, runtime validators, and non-OpenAPI parsers are out of scope.

## When To Use

- You have an OpenAPI 3 source in `knowject/context.yaml` and want TypeScript response types.
- You already generated a `knowject-read-api` client and want to replace `unknown` response generics.
- You want types-only output for manual wiring when no generated client exists.

## Inputs

- `knowject/context.yaml`.
- `api.sources[*]` where `format` is `openapi`.
- `api.client.output_dir`.
- An OpenAPI YAML or JSON file.
- Optional module name if the source path does not make it obvious.

## Outputs

- `<module>.types.ts` under `api.client.output_dir`.
- Optional rewrite of `<module>.ts` generated by `knowject-read-api`.
- Per-endpoint rewrite summary.
- Unified diffs and confirmation prompts before writing.

## Example

User asks:

```text
/knowject types for users
```

Expected result:

```text
The Skill reads the OpenAPI source, emits users.types.ts, and if users.ts was generated by knowject-read-api, shows a diff that imports response types and replaces request<unknown>(...) usages.
```

## Safety Rules

- Refuse without `knowject/context.yaml`.
- Refuse non-OpenAPI sources; do not parse Express, Mongoose, Zod, Pydantic, Spring DTOs, Nest decorators, or markdown specs.
- Only rewrite clients that include the `Generated by knowject-read-api` marker.
- Never overwrite silently; show diffs and require confirmation.
- Keep request parameters and bodies unchanged in Day 1.
- Do not run TypeScript, lint, or tests against the user's project automatically.
